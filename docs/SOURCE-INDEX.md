# Science and learning source index

**KŌMAKU: Shield Protocol · 0.8.0-alpha.1 source snapshot.** Reviewed November 15, 2026, America/New_York. This index distinguishes evidence used by the current window mission from material retained for the earlier advanced mission and reference prototype.

The project lists **ten NASA reference entries**, not ten independent datasets: eight support the current mission, its explanations, or its live solar-image view; two belong to earlier features. One SDO entry includes its image endpoint, data page, and usage rules. The Caltech manuscript and NASA archive entry describe the **same Curiosity study**. The new online view retrieves NASA’s latest available SDO image; it is a browse image, not a raw instrument time series, a live Mars radiation measurement, or a verified Space Apps partner-dataset integration.

The current mission uses one published historical radiation aggregate as the baseline of an **authored rising dose-rate curve**. Dust and rover-power research support the mechanisms. The radiation ramp, pace/fatigue dynamics, panel transmission, hardware, battery capacity, deadline, and cleaned-fraction outcome bands are authored scenario assumptions. See the [parameter and source audit](SCIENCE-JOURNEY-SOURCES.md), [training model](TRAINING-MODEL.md), and [illustrated science guide](SCIENCE-GUIDE.md) for the calculations.

## Live imagery, attribution, and availability

The solar view distinguishes loading, successful online retrieval, stale imagery, cached imagery, and bundled fallback. A server file older than 24 hours is labelled stale; that threshold is an authored interface policy, not proof of when the exposure was taken. A cached image can remain useful but must retain its original retrieval metadata and cached label; reconnecting does not make an old image new. HTTP `Last-Modified` describes NASA’s served file, not a verified camera-exposure time. A successful request establishes access at that moment, not continuous availability or a guaranteed update cadence. The [live-data contract](LIVE-DATA.md) records client states and browser limitations. The [bundled example provenance](../game/assets/nasa/sdo-aia-193-provenance.json) preserves its source, retrieval time, file metadata, and checksum; a bundled example is never labelled live.

NASA requests: **“Courtesy of NASA/SDO and the AIA, EVE, and HMI science teams.”** Its [data rules](https://sdo.gsfc.nasa.gov/data/rules.php) encourage public education use with attribution and say browse products are not intended for scientific analysis or publication without the principal investigator’s consent. We display this browse product as an observation; no scientific model is fitted to its pixels.

Challenge eligibility is a separate question. The supplied brief mentions open NASA data; the official 2026 challenge/resources pages were unavailable during this audit, so a mandatory-live-feed rule was not independently verified. This document makes no eligibility determination.
